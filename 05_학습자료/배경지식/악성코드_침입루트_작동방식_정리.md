# 악성코드 침입 루트 및 작동 방식 — 논문/자료 정리

**작성일**: 2026-09-15
**목적**: 프로토콜 v1.5의 공통 행위 특징(프로세스 생성·네트워크 연결·모듈 로드·레지스트리·파일 이벤트)이 **실제 악성코드의 어떤 행위를 포착하려는 것인지** 그 근거를 정리한다. 논문 3장(위협 모델) 및 6장(조작 난이도 분류)의 서술 근거로 활용한다.

**자료 성격 구분**: 이 분야는 학술 논문만으로는 최신 동향을 담기 어려워, **학술 논문(peer-reviewed)**과 **산업 침해대응 보고서(대규모 실측 데이터)**를 함께 정리했다. 논문 작성 시 전자는 방법론·정의의 근거로, 후자는 현황·비율의 근거로 인용 구분이 필요하다.

## 2. 작동 방식 ① — Living-off-the-Land / 파일리스 ⭐ 우리 연구와 가장 직결

### 2-1. Survivalism: Systematic Analysis of Windows Malware Living-Off-The-Land ⭐ 핵심 학술 논문
**Barr-Smith, F., Ugarte-Pedrero, X., Graziano, M., Spolaor, R., & Martinovic, I. (2021). IEEE Symposium on Security and Privacy (S&P), 1557-1574.**

**핵심 내용**: 약 **3,200만 개의 악성코드 샘플**을 분석한 대규모 체계적 연구. <cite index="57-1">그중 9.6%가 네이티브 바이너리(LOLBin)를 활용</cite>하는 것으로 확인됐다. LOL 기법을 체계적으로 분류하고 탐지 난점을 정리한 이 분야의 기준 문헌이다.

**우리 연구와의 연결**: **이것이 우리 특징 설계의 핵심 근거**다.
- LOLBin 공격은 악성 파일을 새로 만들지 않고 **이미 신뢰된 시스템 바이너리를 오용**한다. 따라서 파일 해시나 시그니처 기반 탐지가 무력하다 → **행위 기반 탐지가 필요한 이유**
- 우리 특징 중 **모듈/이미지 로드율**과 **프로세스 생성률**이 바로 이 유형(정상 바이너리가 비정상적 패턴으로 실행되는 것)을 포착하려는 것

### 2-2. 파일리스 공격의 실측 규모 (산업 데이터)
- <cite index="64-1">CrowdStrike 2026 Global Threat Report 기준, 2025년 탐지 건의 82%에 악성코드 파일이 전혀 포함되지 않았다. 5년 전 51%에서 크게 상승한 수치</cite>다.
- <cite index="55-1">ReliaQuest 2024 연례 보고서에서는 중대 침해 관련 탐지의 86.2%가 파일리스 악성코드와 연관</cite>됐다.
- <cite index="64-1">정상 바이너리가 악성 행위를 수행하면 전통적 안티바이러스는 비교할 대상 자체가 없다</cite>는 것이 문제의 본질이다.

**논문 활용**: 서론에서 "왜 파일 기반이 아닌 행위 기반인가"의 정량적 근거. 단, 벤더 보고서이므로 학술 논문(2-1)과 함께 인용하는 것이 안전하다.

### 2-3. 파일리스 악성코드의 기술적 메커니즘
- <cite index="56-1">파일리스 악성코드는 파일이나 실행파일에 의존하지 않고 침투하여 메모리 내에서 동작하며, 디스크에 흔적을 남기지 않아 탐지를 회피한다. 은닉 스크립트, 내장 VBA/VBS 스크립트, LOLBin 등 정상 도구를 악용해 악성코드를 은밀히 실행</cite>한다.
- <cite index="56-1">Windows에서는 레지스트리 조작과 PowerShell이, Linux에서는 Bash 스크립트·커널 레벨 익스플로잇·메모리 인젝션이 주로 쓰인다</cite>는 플랫폼별 차이도 정리되어 있다.
- 자주 악용되는 바이너리: <cite index="62-1">PowerShell, cmd.exe, rundll32.exe, PsExec가 가장 빈번하게 악용되는 것으로 업계 보고가 일관되게 지목</cite>한다.

**관련 논문**:
- Cross-Platform Analysis of Script-Based Fileless Malware Using Memory Forensics (Springer, 2024) — https://link.springer.com/chapter/10.1007/978-981-97-7426-5_23
- Living-Off-The-Land Command Detection Using Active Learning — https://arxiv.org/pdf/2111.15039
- Living-off-the-Land Abuse Detection Using NLP — https://arxiv.org/pdf/2208.12836

## 3. 작동 방식 ② — 지속성(Persistence) 확보

### 3-1. Evaluation of Persistence Methods Used by Malware on Microsoft Windows Systems
**Dieterich, A., Schopp, M., Stiemert, L., Steininger, C., & Pöhn, D. (2023). ICISSP 2023, 552-559.**
- https://www.scitepress.org/Papers/2023/117102/117102.pdf

**핵심 내용**: 8가지 지속성 기법을 4개 Windows 운영체제에서 **실험적으로 평가**한 드문 정량 연구. <cite index="67-1">운영체제 간 성능 차이는 없었고 대다수 기법이 유사한 점수를 받았으나, Windows 내장 방어 기능을 활성화하면 지속성 기법의 성능이 유의미하게 하락</cite>했다. <cite index="67-1">대부분의 기법이 OS 업데이트를 견디고 지속성을 확립할 수 있었다</cite>는 점도 확인됐다.

**우리 연구와의 연결**: 우리 특징 중 **레지스트리 이벤트율**이 포착하려는 대상이 바로 이것이다.

### 3-2. 레지스트리 기반 지속성의 구체적 메커니즘
- <cite index="65-1">레지스트리를 이용한 "자동시작(autostart)" 메커니즘이 가장 널리 쓰이는 지속성 기법 중 하나</cite>다. <cite index="65-1">시스템 부팅 시 Windows 서비스가 시작되고 Software 하이브의 "Run" 키 항목이 파싱되어 실행되며, 안전 모드로 시작해도 악성코드가 실행되도록 레지스트리를 수정할 수도 있다.</cite>
- <cite index="73-1">MITRE ATT&CK의 "Boot or Logon Autostart Execution" 기법에 속하는 Registry Run Keys/Startup Folder 방식은 사용자 레벨 키를 노릴 경우 권한 상승이 불필요하고, 모든 최신 Windows에서 호환되며, 레지스트리 모니터링이 미흡한 환경에서 자주 간과</cite>된다.

> ⚠️ **우리 프로토콜 6.3절 재검토 필요**: 우리는 레지스트리 조작의 "권한 불필요" 기준을 **X(권한 필요)**로 분류했는데, 위 자료에 따르면 **사용자 레벨 Run 키는 권한 상승 없이 조작 가능**하다. Phase 1~2에서 이 분류를 재검토해야 한다. (14장 변경이력 기록 대상)

### 3-3. 그 외 지속성 기법 (참고)
스케줄된 작업, 서비스 등록, 시작 폴더, COM 하이재킹, DLL 검색 순서 하이재킹, AppInit DLLs 등이 알려져 있다. 이 중 **DLL 관련 기법들은 우리 특징의 "모듈 로드율"과 직접 연결**된다.
- 참고 자료: Exploring Common Malware Persistence Techniques on Windows OS (2023)
