## 2B. 1장 서론 ✅ 설계 확정

**문단 구성**
```
¶1 맥락     ML 탐지 확산, 성능은 주로 단일 탐지 지표로 보고됨 (2~3문장)
¶2 발견     CIC-MalMem: 원 논문 99%, 후속 99.9~99.99% → 깊이 1 트리 99.65%
¶3 확장     한 데이터셋의 문제가 아니다. 탐지 성능은 다른 축도, 해석도 보장하지 않는다
¶4 차별화   Arp et al.의 체계화 → 본 연구는 무엇을 더하나 (명시적)
¶5 접근     연구 질문, DMBD, 4축 진단, 사전 명세, 봉인된 평가셋
¶6 기여     4개 층위 (글머리표 목록)
¶7 구성     논문 로드맵
```

**기여 진술 (4개 층위로 확정, 방법론적 기여는 별도 항목으로 두지 않음)**
1. 벤치마크 층위 — 두 공개 벤치마크가 각각 다른 방식으로 평가를 왜곡함을 보이고 크기를 정량화
2. 모델 층위 — 4축 동시 평가로 구조 차이가 튜닝 차이를 압도함을 보임
3. 개선 층위 — 사전 명세된 비열등성 검정으로 선택적·일괄 개선 중 어느 쪽도 지배하지 않음을 보임 (**부정적 결과를 기여로 명시**)
4. 해석 층위 — 탐지율 기반 해석의 모델 간 차이 대부분이 판단 경계에서 옴을 보임 (탐지율 폭 ≈ AUC 폭 × 8)

**주장하지 않는 것**: 새 프레임워크 제안 / 선택적 개선의 효과 / 일반화 / 선행 연구 반박 / "증명"

**Arp et al. 차별화 (서론 ¶4에서 명시)**

| Arp et al. (2022) | 본 연구 |
|---|---|
| 30편 조사로 함정을 **분류** | 두 벤치마크에서 함정을 **정량화** |
| 함정별 독립적 사례 | **한 연구 안에서 네 층위**에 걸쳐 연쇄적으로 |
| 피해야 할 목록 | 신중한 설계에서도 **해석 단계에서** 빠질 수 있음 |

**¶2 확정 초안 (톤 기준점)**
> 이러한 평가 관행의 한계는 CIC-MalMem-2022에서 선명하게 드러난다. 이 데이터셋은 메모리 기반 난독화 악성코드 탐지를 위해 구축되었으며, 원 논문은 스태킹 앙상블로 99%의 정확도를 보고했다[Carrier]. 이후 연구들은 경량 모델, 부스팅, 교차 어텐션 구조 등을 적용해 이 수치를 99.9~99.99%까지 끌어올렸다[Dener; Sensors; …]. 그러나 본 연구가 이 데이터셋에 깊이 1의 결정트리를 적용한 결과, 단 하나의 분기만으로 99.65%의 정확도에 도달했다. 분기에 쓰인 특징은 실행 중인 서비스 수였으며, 정상 샘플은 대부분 395개, 악성 샘플은 대부분 389개의 값을 가졌다. 서비스 여섯 개의 차이가 악성 행위의 흔적이라기보다 두 수집 환경의 기본 상태 차이일 가능성이 높다는 점에서, 이 결과는 높은 정확도가 무엇을 측정하고 있는지 되묻게 한다.

## 2C. 2장 관련 연구 ✅ 설계 확정

**구성: 논지의 네 층위에 맞춤 (4장과 짝)**
```
2.1 ML 기반 악성코드 탐지와 평가 관행   (도입, Arp et al. 개관)
2.2 데이터셋과 벤치마크 타당성          ↔ 4.1
2.3 탐지 외 평가 축                    ↔ 4.2
2.4 모델 개선과 앙상블                 ↔ 4.3
2.5 평가 지표와 시간적 평가            ↔ 4.4
```

**각 절의 "빈틈" (수정 반영)**

| 절 | 기존 연구 | 본 연구가 채우는 것 |
|---|---|---|
| 2.2 | 지름길 학습(Geirhos, Lapuschkin). **네트워크 트래픽 분야에서 벤치마크 타당성 연구가 진행됨**(Jacobs et al. 2022, BiasSeeker 2026). CIC-MalMem으로 99.9%대 보고 다수 | 이 문제의식을 **호스트 메모리·행위 벤치마크로 확장**, 교란의 **성능 기여 크기**를 분리 |
| 2.3 | MIA(Shokri, Carlini)·강건성(Pierazzi)·자원이 **각각 따로** 연구됨 | 네 축을 **한 모델 집합에 동시 적용** |
| 2.4 | 스태킹·튜닝으로 탐지 성능 향상. 앙상블 이득 한계(Caruana), 다양성-성능 무관(Kuncheva) | 개선이 **다른 축에 미치는 영향**을 사전 명세된 검정으로 비교 |
| 2.5 | 시간적 평가 편향(TESSERACT), MCC 근거(Chicco) | 탐지율 기반 시간 격차에서 **보정과 구분 능력이 섞이는 문제** |

**한정어 원칙**: "~는 드물다"가 아니라 "본 연구가 확인한 범위에서는~"으로 서술. 체계적 문헌 조사를 수행하지 않았으므로.

**2.2의 이론적 닻**
- Lapuschkin et al.: "표준 성능 평가 지표는 다양한 문제 해결 방식을 구분하지 못할 수 있다" → 중심 주장과 직결, **서론 ¶3에도 활용 가능**
- Geirhos et al.: 지름길의 정의 — 단, **전이 실패를 시험하지 않았으므로 "지름길일 가능성이 높다"로만**

## 2A. 3장 연구 설계 ✅ 확정

**원칙**: 4장의 결과를 이해·재현하는 데 필요한 것만 3장에, 나머지는 부록.

**목차**
```
3.1 연구 질문과 가설
3.2 사전 명세와 변경 관리
3.3 데이터 (DMBD 주실험, CIC-MalMem 사례연구, 특징 12개)
3.4 분할 설계
3.5 모델
3.6 진단 축과 측정
3.7 개선 전략
3.8 통계 처리
```

**⚠️ 표현 원칙 — "사전등록" 사용 금지**
- 사전등록(preregistration)은 OSF·AsPredicted 등 **공개 저장소에 타임스탬프로 등록**해 제3자가 검증 가능한 것을 뜻함
- 본 연구의 프로토콜은 **내부 문서** → 결정 시점을 외부에서 검증 불가
- 논문에서는 **"사전 명세(pre-specified protocol)"**로 표현하고, "실험 착수 전 분석 계획을 문서화하고 모든 변경을 사유와 함께 기록했다"로 서술
- **공개 등록이 아님을 한계로 명시**하고, 변경이력 전문을 부록 A로 공개

**연구 과정 변화의 3단 처리 기준**

| 성격 | 처리 | 예시 |
|---|---|---|
| 그 자체가 **결과** | 4장에서 다루고 3장은 참조만 | CIC-MalMem 교체(→4.1), H4 폐기(→4.1) |
| **해석에 영향** | 3장에 짧게 + 부록 참조 | §10.1 발동기준 복원, 교란학습 샘플 출처, 탐색예산 해석 |
| **절차적** | 부록 A에만 | F1→MCC, TPE→GP-EI, HistGB 대체 |

| 번호 | 내용 | 역할 | 상태 |
|---|---|---|---|
| 분할 다이어그램 | 평가셋 4종의 규모·비율·용도·봉인 | 3장·4장 전반의 참조점 | ✅ |
| 표 | 가설과 성격 (H1~H5) | **판정 결과는 넣지 않음** (결과 선반영 방지). H4만 "폐기" 표기(설계 단계 사실) | ✅ |
| 표 | 모델 구성 (A·B·C·D) | 설계상 역할과 튜닝 여부 | ✅ |
| 표 | 진단 축 (4축, 주지표, 방향, 측정조건) | 4장 그림의 ↑↓ 표시의 근거 | ✅ |
| 표 | 개선 전략 구성 (선택적 vs 일괄) | 구성요소와 허용한도 필터 적용 여부 | ✅ |

**배치 결정**: 선택된 구체값(20트리, msl=10, 이산화 1자리, 증강 40%)은 3장이 아니라 **4.3 본문**에. 3장은 후보 공간과 선택 규칙까지만.

## 3. 그림·표 목록

### 4.1 벤치마크 층위 ✅ 확정

**이야기 구조**: 두 문제를 **동등한 무게**로 보고하되, **성격의 차이**로 절을 마무리한다.
- CIC-MalMem: 문제가 성능 **전부**를 설명 → 사용 불가
- DMBD: 문제가 측정 가능하고 **한정됨**(약 0.03 MCC) → 한계를 안고 사용 가능
- 이 마무리가 없으면 4.2~4.4(전부 DMBD 기반)의 신뢰도가 흔들린다

| 번호 | 내용 | 메시지 | 상태 |
|---|---|---|---|
| 그림 1 | CIC-MalMem `svcscan.nservices` 분포 (정상 vs 악성) | 평균 차이 1.5%인데 분포가 거의 안 겹친다 | ✅ |
| 그림 2 | DMBD 연도별 클래스 구성 (**모자이크**, 폭∝표본수) | 악성은 옛날, 정상은 최근에 몰려 있다 | ✅ (n라벨 겹침 수정 필요) |
| 표 1 | 결정트리 깊이별 정확도 + 다수클래스 기준선 | 깊이 1 트리 하나로 99.65% | ✅ 각주: "후속 연구 보고치 99.9~99.99%" (**100% 아님**, references_verified.md 참조) |
| 표 2 | 연도 교란 영향 분리 (a)(a′)(b)(c) | 교란은 실재하나 제거해도 MCC 0.78 유지 | ✅ |

**결정 사유 기록**
- 그림 2를 일반 막대 대신 모자이크로: 2017(n=32,164)과 ≤2016(n=287)이 같은 폭이면 작은 연도가 과대 표현됨. 데이터가 두 덩어리(2017 vs 2023~24)로 갈린다는 핵심을 면적으로 전달
- 그림 3(두 벤치마크 비교)은 제외, 표 1에 기준선 열로 흡수
- 표 2에서 (d) 2021년 단독 제외: n=3,205로 표본 효과와 교란 효과가 분리되지 않음

**⚠️ 수치 범위 주의**
- 그림 2는 **전체 데이터셋(64,747)**: 2024 악성 16%
- Phase 5의 "2024 악성 0건"은 **Train+Val 한정**. DMBD가 2024 악성을 전부 공식 test에 배치했기 때문
- 4.1에서는 전체 데이터, H4 폐기 설명(3장 또는 한계)에서는 Train+Val 수치 사용

### 4.2 모델 층위 ✅ 확정

**하위 구성 (흐름순)**: 시야가 넓어지는 순서
```
4.2.1 탐지 성능만 보면        → H3
4.2.2 다른 축을 함께 보면      → H1
4.2.3 특징 수준으로 들어가면   → H2
```

| 번호 | 내용 | 메시지 | 상태 |
|---|---|---|---|
| 표 3 | 모델 4종 종합 결과 (탐지 6지표 \| 진단 3지표) | 정확한 수치 참조 | ✅ |
| 그림 3 | H3 포레스트 플롯 (튜닝·스태킹·구조 효과) | 구조 차이가 튜닝을 압도한다 | ✅ |
| 그림 4 | H1 4축 소형 다중 그림 (실제 값+CI) | 탐지 성능이 다른 축을 보장하지 않는다 | ✅ |
| 그림 5 | H2 산점도 4패널 (중요도 vs 민감도) | 대체로 비례하나 net_connect는 예외 | ✅ |

**결정 사유 기록**
- **H1을 순위 차트 대신 실제 값+CI로**: B(탐지 1위)의 프라이버시 3위 반례는 C와 차이 0.0029, CI가 거의 완전 중첩. 순위 차트는 이 미미한 차이를 명확한 순위차로 과장함
- **지연시간은 1,000회 p50 사용**: 20회 평균보다 안정적. §10.1 발동 판정은 20회 값으로 했음을 각주로 명시
- **그림 3 음영 라벨은 "실질적 차이 기준 ±0.05"**: §10.2 허용한도는 한쪽 방향(저하 상한)이므로 "허용 한도"라 부르면 부정확
- **그림 5 패널별 y축 척도 상이 명시**: H2는 모델 내부 상관을 묻으므로 척도를 따로 두되, 패널 간 비교를 막는 각주 부착(D 민감도는 트리의 약 1/8)
- 직렬화 크기(§7.1)는 탐색적 분석이므로 표 3에서 제외, 논의의 실무 함의로

### 4.4 해석 층위 ✅ 확정

**위치**: 결과에 둔다. 두 사례 모두 AUC 재계산이라는 정량 근거가 있어 결과로서 자격이 충분하며, 중심 주장의 네 번째 근거가 된다.

**서술 방식: 현상 중심 (ⓑ)**
- "탐지율로는 X처럼 보이지만, AUC로는 Y다"로 서술 — 누구나 빠질 수 있는 일반적 함정으로 전달
- 연구자가 처음에 잘못 해석했다는 **경위는 한계·부록에** 투명성 차원에서 기록

**4.4를 하나로 묶는 발견**
```
RF 계열 5개 모델, 2024 코호트
  탐지율 폭 0.086  vs  AUC 폭 0.011   → 약 8배
```
모델 간 탐지율 차이의 대부분이 구분 능력이 아니라 **판단 경계(보정)**에서 온다. 일괄과 B는 그 양 극단.

| 번호 | 내용 | 메시지 | 상태 |
|---|---|---|---|
| 표 5 | 공식 Test 코호트별 결과 (6모델) | 시간 격차 열 옆에 AUC 열 — 순진한 관점과의 대비를 미리 깔아둠 | ✅ |
| 그림 7 | 탐지율 vs AUC 산점도 (**가로·세로 눈금 간격 동일**) | 탐지율은 좌우로 퍼지나 AUC는 평평 → 구분 능력 차이 아님 | ✅ |
| 그림 8 | 평균 확률 덤벨 (AUC 순 정렬) | **판단 경계의 위치**가 다르다 (일괄: 정상↑, B: 악성↓) | ✅ |

**그림 설계 결정**
- 그림 7은 `set_aspect('equal')`로 고정. 자동 척도면 세로축이 늘어나 AUC 차이가 부풀려짐 → "8배"를 정직하게 보이려면 필수
- 그림 7에서 D는 **"진짜 구분 능력 차이의 기준점"**으로 포함 (대각선 방향으로 떨어짐)

**⚠️ 설계 중 발견한 오류 — 기록**
- 최초 제안에서 그림 8의 "두 점 사이 거리 = 구분 능력"이라고 했으나 **틀렸다**. 평균확률 간격 순위와 AUC 순위가 불일치(일괄: 간격 5위 / AUC 3위, 선택적: 간격 3위 / AUC 5위)
- 원인: AUC는 두 분포의 **겹침**을 보는데 평균 두 개로는 알 수 없음. 일괄은 정상 분포를 통째로 이동시켰을 뿐 순서는 유지
- 조치: "간격" 열 삭제, AUC 순 정렬, "거리 ≠ 구분 능력" 각주 부착. **그림 역할 분리** — 그림 7=구분 능력, 그림 8=판단 경계 위치
- 의의: 거친 요약(평균)을 구분 능력 지표처럼 쓰는 것은 본 논문이 경고하는 바로 그 실수. 수정하지 않았다면 그림 7과 모순
